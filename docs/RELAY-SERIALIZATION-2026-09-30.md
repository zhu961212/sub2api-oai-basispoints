# 工具 relay 序列化兼容修复（2026-09-30）

## 报告范围

本次报告包含多账号、直连与不同代理的同类失败：
`invalid_tool_call` / `invalid_request_error` /
`Basis Points returned a malformed or ambiguous client tool relay envelope`。
流式事件序号包括 4、84、85 和 308；序号只表示流内位置，不标识不同根因。

所提供的终态错误没有原始工具 arguments，不能据此判断具体请求损坏了哪一层，
也不能据此认定账号失效、代理故障或请求被重复执行。以下修复针对已在本地
复现、能产生完全相同错误消息的序列化缺口。

## 修复

1. 外层 arguments 的 code 字符串遗漏了一层 JSON 转义时，只在字符串内部
   已经是一个完整、严格、无歧义的 JSON 工具信封时恢复。恢复的是原始文本
   切片的序列化，不猜补源码引号或截断参数。恢复后再次严格验证整个外层对象。
2. 字符串内控制字节现在覆盖完整的 0x00–0x1f 范围，包括 NUL、退格和换页，
   转换为同一个字节的 JSON 转义。此前只恢复回车、换行和制表符。
3. 保持工具目录和参数 schema 校验、重复键及多候选拒绝、解包层数与大小
   限制；保留原始 native call 的重放身份、custom input 首尾空白、反斜线及
   大整数。确定性恢复不增加上游请求次数。

## 回归覆盖

- 协议层先添加失败用例：外层 code 漏转义、NUL 控制字节均复现原始错误；
  再应用修复，确认原用例转为通过。
- 32 种控制字节 × 内层 code / 外层 code 对象 / 外层 code 字符串，共 96 组；
  同时检查逐字节保真、原始调用重放、合法转义、嵌套函数数据。
- 外层漏转义覆盖 code 字段顺序、空白、四层解包边界、9007199254740993 大整数
  以及重复字段、多对象、截断、过大内容等拒绝情况。
- 新增 68 组 transport 组合，覆盖客户端 JSON/SSE × 上游 JSON/SSE：
  52 组成功恢复、16 组歧义拒绝。检查调用身份、input 字节、上游请求次数、
  唯一工具生命周期、完成/失败状态与流结束，不向客户端释放无效工具参数。

本记录只说明本地源码和模拟上游验证；未替换线上插件、未发布新版本，
也未使用真实账号回放上述历史请求。
