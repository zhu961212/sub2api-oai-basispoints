# 0.6.9：双版本宿主兼容与原生 XHigh 检测修复

修复日期：2026-09-27；发行日期：2026-09-28。插件 ID：local.oai-basispoints。本发行合并此前未发布的 0.6.8 和 0.6.9 修复，支持官方 Sub2API 0.2.8 / 0.2.9。发布附件和最终校验结果以 GitHub Release 为准；发布不等于部署服务器。

## 双版本兼容与升级

- 同时支持官方 Sub2API 0.2.8 和 0.2.9，推荐 0.2.9；清单列出两个已测试版本，保持原有版本范围 >=0.2.8 <0.3.0。
- 两版本插件契约、UI Bridge、安装器和宿主反向服务保持一致；无需打宿主补丁或重新编译 Sub2API。官方标签、源码及验证边界见 [双版本兼容记录](COMPATIBILITY-0.2.8-0.2.9.md)。
- 合并 0.6.8 的空完成事件答案恢复、原生探针客户端标识及固定 gpt-6-astra / xhigh 修复，和 0.6.9 的后台超时预算修复。
- 安装包包含 Windows amd64 与 Linux amd64 运行时，继续使用 oai-basispoints-v1 Ed25519 签名身份与原公钥。升级前备份现有配置，按宿主插件管理页支持的安装流程上传新包并核对版本 0.6.9。若宿主要求先卸载，卸载会删除插件配置，需重新设置模型、账号、开关、绑定与灰度。

## 用户回传与原因

- 用户回传 #284、#288 回答 iPhone 15 Pro Max，按既有固定规则显示疑似降智；#276 回答 iPhone 17 Pro Max，符合规则。
- #287、#277、#280 报告 upstream 完成前超时；#198 仍由宿主标记不可调度而跳过。以上是用户回传，未由本次维护重新请求账号。
- 代码仍保留原低预算探针的单账号 20 秒、整批 24 秒限制；即使 HTTP 配置默认 300 秒，更短的 context 也会提前取消请求。后台执行器还额外限制 30 秒，界面在同时具备两种能力时优先旧同步接口。
- 本次只有 6 个可调度账号，低于并发上限 8，优先排查单账号预算。现有超时文案也覆盖网络连接超时；仅凭用户文本不能断言三个账号均恰好耗尽 20 秒，也不能保证延长预算后所有账号都成功。

## 修复行为

- 单号、批量、自动后台检测每账号使用配置快照的 timeout_seconds，默认 300 秒；保持原生 gpt-6-astra + XHigh，不改问题、不降档、不走 BPS 检测。
- 每批并发不超过 8。手动扫描按目标批次数计算总预算，请求预算之和最多 30 分钟，另留 5 秒余量；自动调度仍按最多 8 个账号一批公平推进。
- 每个账号单独从宿主解析 OAuth 身份及绑定代理，并使用对应代理发送原生请求；未绑定代理时直连。允许多个账号配置同一代理，也允许不同代理使用同一出口 IP，不按 IP 合并、去重或跳过账号。账号凭据独立，不可调度账号不发送探针。本地 CONNECT 代理回归覆盖独立代理与共享代理两种并发场景。
- 后台执行器移除旧 30 秒封顶，任务仍受完整扫描预算与运行实例取消控制；旧同步入口仍保持 20 秒/24 秒兼容限制。
- 配置页优先后台任务，按任务公告的 execution_timeout_ms 查询，留 10 秒收尾；未公告后台能力时才回退旧同步接口。后台忙碌不会触发同步绕行。
- 查询窗口结束仍可继续查询同一任务；不把未确认结果描述为确定检测失败，不自动重提或消费更多账号额度。
- 已完成结果仍须来自成功终态；超时、跳过、未完成均不进入降智或恢复判定，已有路由不凭错误改变。
