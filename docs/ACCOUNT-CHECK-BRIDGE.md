# 账号检测：官方 UI Bridge v1 的接口边界

本说明包含 0.6.0 的旧宿主边界，以及 0.6.1 配套宿主的检测恢复。0.5.28 的历史行为见对应发布记录；0.6.1 的发行与验收见 [发布记录](release-0.6.1-2026-09-27.md)。

## 0.6.1：配套宿主恢复检测

需要同时更新并重新构建 Sub2API 宿主的前后端及本插件，启用插件后重新打开配置页。只更新插件不能让旧宿主获得检测能力；旧页面也需重新打开以协商能力。

- 宿主 UI 会话提供 capabilities=[config.testScoped]，通过 config.load 回复交给插件。未明确声明能力时，检测继续禁用并说明原因。
- config.testScoped 将本次 request_id 和 config 快照发送到 POST /admin/plugins/:id/test-scoped，沿用管理员鉴权和二次验证。宿主验证快照后直接调用 TestConfig，不保存或 Apply 该快照，不从共享配置重读目标。
- 宿主通过 gRPC metadata 标记 x-sub2api-test-scope=request-v1、x-sub2api-test-request-id。插件仅在标记合法且目标明确时放行，普通 TestConfig 和遗留持久触发仍不能调用账号。
- 单号传 degradation_check_account_id，批量传当前完整列表的 degradation_check_account_ids；两者互斥，批量最多 10,000 项。后续新增账号不会加入正在执行的检测。不可调度、已停用或已消失的账号返回 skipped。
- 结果包含 request_id、target_account_ids 和逐账号结果，页面校验请求及目标归属。单号不修改选择；批量仅在完整返回且存在确认的疑似降智账号时更新本地勾选，失败、跳过和列表外账号保留选择，保存后生效。检测从不自动保存表单。
- 403 自动停用继续作用于实际检测账号；未保存的恢复勾选不能授权检测。请求使用当前表单配置快照，路由配置不因此应用。
- 宿主对同一插件及 request_id 在本进程内缓存最多 256 个结果、保留 10 分钟，重复快照直接返回缓存，冲突快照拒绝，失败和取消也不重复派发；容量满时拒绝新请求。此去重不跨进程重启或多实例，客户端不自动重试账号检测。

回归包含两个配置页并发、请求目标及配置隔离、批量目录快照、旧宿主禁用、失败结果与 403 恢复保护。验证使用本地模拟账号及上游，不代表已部署或真实账号验收。

## 0.6.0 及未升级宿主的行为

官方 Sub2API 0.2.8 的 UI Bridge v1 不能把单次检测和调用页面选择的账号原子绑定。0.6.0 暂停配置页的单账号与批量主动检测，禁用按钮并显示原因。页面不再保存检测触发字段、不调用账号检测、不做收尾保存；两个页面同时点击或直接触发按钮事件也不会覆盖配置、消费账号额度或由检测引起 403 停用。

服务端 TestConfig 同样拒绝遗留 degradation_check 或目标字段，防止尚未关闭的旧页面和已保存旧标记继续触发错误账号请求。拒绝发生在目录枚举、凭据解析和上游请求之前。旧配置仍可加载，普通保存会清除旧标记。

以下功能继续可用：

- 普通模型和账号配置保存、403 自动停用开关及明确手动恢复。
- plugin.status 被动查询账号目录、可调度性、403 停用状态和持久化错误。
- 宿主普通“测试配置”的 TCP/TLS 连通性检查，不携带账号凭据，也不发送 HTTP 请求；它不能验证账号的 BPS 权限。
- 已有检测摘要的被动展示和按账号 ID 对应，不再自动发起新的检测。

## 官方代码核对

核对本地官方 0.2.8 源码，提交 a3eb7ef302961cba716dc78b39b93b60c467db0e：

| 位置 | 实际契约 |
| --- | --- |
| backend/pkg/pluginapi/docs/ui-bridge.md | config.test 无参数，只测试已保存配置；plugin.status 必须无副作用。iframe CSP 禁止外部网络，且不暴露管理员令牌。 |
| frontend/src/api/admin/plugins.ts | POST /admin/plugins/{id}/test 没有请求正文。 |
| backend/internal/service/plugin_manager.go / SaveConfig | 每次保存独立获取 operationMu；先 Validate/Apply，再加密写数据库。数据库保存失败时会恢复并重新应用旧配置。 |
| backend/internal/service/plugin_manager.go / Test | 测试独立获取 operationMu，从数据库重新加载配置，重新 Validate/Apply，再传给 TestConfig。 |
| backend/pkg/pluginapi/v1/plugin.proto | TestConfigRequest 只有 config_json，没有独立目标、调用快照或配置 revision。 |

因此 save(账号 1) → save(账号 2) → test → test 允许两次测试都读到账号 2。页面 busy 锁只覆盖当前 iframe；测试后核对结果只能阻止错结果显示，不能撤销已经发生的请求。额外读取共享配置也仍存在读取到派发间隙。

把请求放进 ValidateConfig 或 ApplyConfig 不构成兼容修复：这些回调会在保存、启动、测试和回滚等生命周期重复执行。保存还有先应用、后落库和 15 秒期限；无法把一次性、可能计费的主动请求可靠地绑定到用户检测意图。将其塞入 Health 则直接违反被动状态契约。

## 恢复主动检测的前提

需要官方宿主提供经鉴权和二次验证的原子检测入口，按本次请求传入目标账号及所用配置快照（或提供有 CAS 语义的配置版本），而不是从共享配置重读临时命令。目标和配置必须在凭据解析及派发前确定；并发的其他保存不能替换目标。测试不得修改持久账号路由，结果应携带本次请求 ID 和实际目标；批量检测也应提交明确快照。还需确认重试、超时、重启和回滚不会重复消费同一检测命令。

0.6.0 未增加未经官方实现的 Bridge 消息、绕过 iframe 限制或修改官方宿主，也不宣称新版宿主已经支持此接口。底层私有探测器保留，用于隔离和协议回归；它不是可供旧 UI 使用的安全入口。

## 回归验证

- tools/ui.test.cjs：两个真实 app.js 页面共用同一配置存储，普通点击和强制事件都保持零保存、零测试派发；待保存设置和明确的 403 恢复选择仍保留。旧版事务功能测试迁移为此安全边界和被动展示回归。
- internal/transport/degradation_bridge_test.go：遗留目标和批量触发、重复 ApplyConfig、并发 TestConfig 都不能解析凭据或发送账号请求；普通连通性和目录状态仍可用。
- 原账号凭据、代理、结果及终态隔离回归继续直接测试私有探测器，不再把直接传配置的单元测试误当作官方 UI 端到端原子性证明。

以上仅使用本地模拟目录、响应和上游，不调用真实账号。
