# 0.6.3：空模型透传与 C 源码工具封装修复

日期：2026-09-27（UTC+8）。插件 ID 为 local.oai-basispoints，签名继续使用
oai-basispoints-v1 和原 Ed25519 公钥。适用 Sub2API >=0.2.8 <0.3.0，
原版宿主验证基准为 a3eb7ef302961cba716dc78b39b93b60c467db0e。

## 空模型选择

清空模型并保存仍然表示全部走宿主指定的原上游，不恢复默认勾选。
插件以前只使用连接 URL，未恢复 ForwardRequestStart 独立传入的 Host；
URL 与虚拟主机不同的部署可能因此失败。本版保留宿主 Host，Host 为空时
继续使用 URL 默认值，账户代理、Bearer、请求正文及响应内容保持原有语义。

原版 0.2.8 的 Forward 协议没有“跳过插件并回退原连接”的信号，返回空帧
或伪造 skip 错误会变成插件传输错误。本版继续通过插件执行原上游透传。

## C 源码及工具纠正

合法序列化的 custom 工具输入逐字节保留，包括 printf 双引号、C 转义、
Windows 路径、中文、首尾空白和多行 apply_patch。

本版扩展仅供一次重新生成使用的资格判断：必须能确认一个已声明的 custom
工具，元数据完整，字符串边界唯一，且损坏属于可保守识别的字符串语法。
覆盖工具名在前、字符串参数在后，以及 args 在前、唯一 tool 字段在后的
两种常见封装顺序；额外或冲突的尾部元数据仍然拒绝。
原始坏调用不交给客户端执行，也不会先猜测或修补 C 代码；它只作为已拒绝
调用反馈给同一次 Forward 的上游。纠正后的调用必须重新经过完整校验，
并保持同一个 custom 工具的规范名称；不能借纠正切换到另一种工具。

重复字段、多候选、结构冲突、未知工具、未完成工具历史、失败终态和超过
包装层数的输入仍然拒绝。纠正最多一次，第二次仍无效就返回明确失败，
不无限重试、不换模型、不换账号、不重复已执行工具。

## 错误 #40874 的失败分类

0.6.2 已为本地生成的 invalid_tool_call 补充请求级错误类型，但上游直接
返回的现成 response.failed/error 走另一条归一化路径，仍可能缺少类型，
甚至把 SSE 的 response.failed 当成 error.type。原版宿主因此可能换号，
最后用 Upstream service temporarily unavailable 覆盖真实原因。

本版补齐相关工具失败的请求级分类，保留可安全返回的错误码和诊断。
同时修复嵌套 JSON 失败响应在非流式转换时丢失原有诊断的问题，失败响应
中的工具输出仍然不交给客户端执行。
普通服务端、网络及限流错误继续遵循原有策略；未选模型的普通宿主响应
不因此被任意改写。用户日志没有原始工具参数，本版针对可复现的同类
语法失败和已确认的分类漏口修复，不从终态日志猜测或执行源码。

## 验证与发行

验证覆盖 Go 离线回归与 vet、Linux CI 竞态检查、UI/Python 发布工具、
C 源码的 JSON/SSE 及流式/非流式组合、无效纠正的次数上限，以及原版
宿主真实插件进程的空模型透传和错误分类。发行包使用独立验包器强制
校验签名、key_id 和全部成员哈希，公开上传后重新下载核对。

这些测试使用本地合成账号和上游，不运行 TestLive，不等同于真实账号
或生产 Linux 宿主实测。精确源码提交、CI 结果和最终包校验以本次 Release
及其 SHA-256 附件为准。发布不自动修改正在运行的服务器。

## 安装

1. 停用并卸载旧插件；旧插件配置随卸载删除。
2. 上传 local.oai-basispoints-0.6.3.s2plugin 签名安装包。
3. 重新配置模型、账号、403 开关、绑定和灰度比例，然后启用。
4. 关闭旧配置页重新打开，确认宿主实际运行版本为 0.6.3。

不兼容或迁移旧版插件配置。宿主 trusted_publishers 中的原公钥无需更换。
0.6.1 继续保持撤回。
