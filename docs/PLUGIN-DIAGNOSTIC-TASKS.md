# 无宿主补丁的账号检测

日期：2026-09-27。该功能在插件内实现，使用官方 Sub2API 0.2.8 已有的
UI Bridge v1、HostService 账号目录、出站身份和插件 KV，不要求应用
0.6.1 的宿主补丁。兼容任务协议最初随 0.6.2 发布，历史产物与验证范围见
[0.6.2 发行记录](release-0.6.2-2026-09-27.md)。

本页同时描述 0.6.7 新增的原生探针及自动检测，发布不代表线上实例
已经安装更新或完成真实账号验收。自动调度详见
[原生自动检测与切换](AUTO-NATIVE-DEGRADATION.md)。

## 操作语义

- 单号检测提交一个账号；一键检测固定点击时的账号目录快照。
- 当前源码中，单号、批量与自动探针均固定请求原生 Codex，即使账号业务
  已经走 BPS 也不例外；使用同一账号的宿主 OAuth 身份与关联代理，拒绝
  重定向，不使用 BPS responses_url、已选模型列表或请求体转换。
- degradation_check_model 独立控制原生模型，默认 gpt-5.4。
- 每个任务使用独立任务编号，账号和检测参数在准备后不可替换。
- 页面通过两次已有的 config.save 消息准备和确认任务，通过 plugin.status
  查询结果；不通过普通 config.test 启动任务。
- 命令必须独立提交，不能把页面待保存的账号选择或 403 恢复设置覆盖到
  生产配置。普通保存继续按原规则生效，检测结果不自动保存账号选择。
- 单号结果不修改选择。未开启自动模式时，批量只有完整的可信结果可以
  改变本地勾选；失败、跳过和列表外账号保留原选择，点击保存后才改变路由。
  自动模式下手动批量也只显示结果，不代替自动调度的连续两次确认。

## 自动周期与手动任务的区别

当前源码的 auto_degradation_enabled 默认 false；开启并保存后，后台按
auto_degradation_interval_minutes 执行，默认 30 分钟、范围 5–1440 分钟。
首次或新账号到期时间分散在约 5–30 秒后；待确认结果固定约 5 分钟复测，
连续两次有效结果一致后才启用 BPS 或取消 BPS，失败和跳过不改变路由。

自动账号状态单独写入 native_degradation_v1 插件 KV，重启恢复有效路由
与后续计划，不复用手动任务编号，也不自动重放旧手动任务。自动检测每批
最多 8 个账号、扫描预算 24 秒；较大目录按到期时间排序，分批公平推进，
并非整目录必须在 24 秒内完成。自动探针与手动探针不会同时运行。

配置页在自动模式下锁定账号手动改选，并显示后台实际有效路由。关闭自动
并保存会取消在途自动探针、停止后续调度，保留最后有效路由；之后可手动
重新选择并保存。该状态不等同于生产配置中的原始账号选择快照。

## 协议

新命令的外层只包含 diagnostic_task；准备阶段包括协议版本、运行实例
owner_id、task_id 和检测配置快照；确认阶段包括同一 owner_id、task_id
及准备成功后得到的随机回执。宿主仍保存插件归一化后的配置。

插件 ValidateConfig 将命令包装到当前生产配置，并加上当前实例的密封校验。
ApplyConfig 更新任务状态及入队；合法已保存信封仍可恢复对应的生产配置，
让宿主保存失败后的回滚保留原语义。后台任务执行器处理上游请求，
Health 返回 diagnostic_tasks 的只读快照，不解析检测凭据、不启动任务。
普通 TestConfig 只解析信封内的生产配置并进行 TCP/TLS 探测，不执行命令。

## 可靠性边界

1. 当前运行实例串行处理兼容手动任务，并与自动检测互斥。其他任务收到
   忙碌反馈；多副本及运行实例
   切换不承诺透明接续，owner 不匹配时停止提交。
2. 上游请求前先写入任务消费记录。KV 不可用时不执行检测；重复确认、
   普通测试重新应用配置、宿主回滚和进程重启不能自动重发旧任务。
3. 旧宿主先 ApplyConfig，再持久保存配置。因此确认保存失败或超时时，
   任务仍可能已经入队或执行。界面必须按任务编号查询，不能把保存失败
   等同于未执行，也不能自动创建新任务重试。
4. 进程中断后的不确定结果不自动重跑；无法确定是否发出过请求时明确
   保留不确定状态。该协议不承诺跨副本或故障场景的“恰好一次”。
5. 检测遵循宿主账号可调度性。BPS 403 停用不阻止原生检测，原生 HTTP
   或流内 403 只算检测错误，不写入 BPS 停用记录。已有 BPS 403 保护仍
   优先于自动启用结果；自动检测和待保存的恢复勾选都不能解除它。
   真实检测会消耗上游额度，固定“苹果17”规则不代表通用智力测评。
6. 准备任务两分钟过期；实例内最多保留 32 条任务，结果保留 30 分钟；
   KV 消费记录保留 24 小时。已发出确认的任务仅继续查询，不重发确认。
   准备保存已确认但尚未获得回执时，继续查询可以完成尚未发送的首次确认。
7. 宿主 KV 每条记录上限 256 KiB，大结果可能无法持久保存；消费记录不会
   因结果写入失败而重试执行。旧实例结果不能通过新实例透明恢复。

## 可重复验证

tools/host-diagnostic-integration/run.py 使用未应用补丁的基准
a3eb7ef302961cba716dc78b39b93b60c467db0e。运行时从 Git 导出原版宿主
backend，仅通过 Go overlay 增加测试文件；不修改宿主工作副本或生产实现。
它调用真实 PluginManager 和插件子进程，检查单号、批量、生产路由字段
不变、双页面任务隔离、重复确认、保存失败回滚、普通测试、重启和 KV 故障。

源码集成命令：python tools/host-diagnostic-integration/run.py --host-source <基准仓库路径>。
当前固定原生端点的跨进程模拟使用仅测试的 Go overlay 与环境变量，严格只
允许 http://127.0.0.1:<port>。工具明确拒绝 --plugin-binary 模式：实际安装包
的固定原生端点不能用该模拟替换，不能据此声称完成包验收。此工具也不替代
安装包签名验证或真实数据库部署验收。UI 模拟回归使用 node --test tools/ui.test.cjs，
真实浏览器沙箱回归使用 node tools/test-ui-browser.mjs。

当前原生探针的本地测试使用合成账号、模拟 RoundTripper 或本地 HTTPS
代理，不通过修改生产原生 endpoint 来注入测试地址。真实原生探针另需
显式设置 BASISPOINTS_LIVE_NATIVE_DEGRADATION=1 和授权测试凭据。
0.6.7 发布验证区分源码 loopback 诊断集成与正式签名包安装、转发验收，
具体通过结果及 CI 链接记录于 GitHub Release。本地回归不代表生产部署
或真实账号验收；历史 0.6.2 集成记录不能替代当前源码验收。
