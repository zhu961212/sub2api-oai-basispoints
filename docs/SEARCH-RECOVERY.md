# 联网搜索与 403 自动复查

日期：2026-09-30。本文描述当前工作区新增功能，不代表已安装到运行中的服务。

## 联网搜索

BPS 不提供原生托管联网搜索。启用 web_search / web_search_preview 等托管搜索、明确强制搜索，或者历史中包含 web_search_call 时，插件将整次请求透传至宿主选择的原生上游。模型、账号、代理、搜索选项、引用及 JSON/SSE 响应保留原生语义。即使模型最终没有调用搜索，只要声明了启用的托管搜索，也采用原生路由。

客户端自己执行的 function/custom 搜索工具仍可使用 BPS。tool_choice=none 禁用的新搜索声明不会单独触发切换，但已有原生搜索历史仍走原生。搜索透传发生在 BPS 状态读取、账号身份解析和附件上传之前，不受 BPS 状态存储失败阻断。原生接口自身报错仍如实返回，其 403 不会创建 BPS 停用记录。

## 403 停用和每 6 小时复查

- 保留默认开启的“403 自动停用”开关。任意明确 BPS HTTP 403 或错误信封中的明确 403，立即停止该账号的 BPS 转发。其他账号不受影响，后续业务请求可走宿主原生路径。
- 首次复查安排在停用后 6 小时；仍未恢复时，每 6 小时复查一次。旧停用记录没有时间戳，首次加载新代码后从迁移时间开始安排 6 小时。
- 复查使用该账号自身令牌和代理，对一个已启用的 BPS 模型发送最小真实推理。仅访问检查接口返回 allowed=true 不能证明推理已恢复。复查可能消耗少量账号额度。
- 只有推理成功完成且没有 403 才解除当前停用。超时、网络故障、401、429、5xx、重定向、损坏或未完成的响应不会误判为解禁，仍按下一轮计划复查。检测不自动重放。
- 停用时间、下次复查时间和恢复标记写入宿主 KV。请求前先持久化下一次复查时间，因此进程重启不会立即重复已发出的复查。新的 403 会生成新的停用标识，旧检测结果不能解除它。
- 关闭 403 开关或取消全部模型时暂停复查；已排除或宿主不可调度的账号不发送复查请求。原生降智检测决定不使用 BPS 的账号也不复查 BPS。
- 页面只显示临时停用状态，普通保存不会把临时 403 自动变成永久手动排除；恢复后继续遵循原账号及模型选择。仍可明确重新勾选并保存手动尝试恢复。

存储失败时不冒险恢复。计划持久性依赖宿主 KV；旧宿主没有 HostService 时只能维持进程内停用，无法执行后台账号复查。本实现沿用单插件实例的状态协调，不提供多个运行副本之间的分布式探针锁。

升级前已经保存到账号排除表的历史选择无法区分是用户手动排除还是旧页面因 403 自动排除；不会擅自清除这些排除项。需要恢复此类账号时，先明确重新选择并保存。新代码产生的临时停用不会再导致这个问题。

## 宿主兼容性

上述功能使用现有 Plugin API、账号目录及 HostService KV，不需要宿主源码补丁。BPS 使用范围继续由原有账号、模型和自动路由设置决定。

## 验证范围

回归使用本地模拟上游和合成账号；不读取真实账号凭据，不代表真实账号已经解禁。源码测试通过也不等于已更新运行中的插件或宿主。

本地回归覆盖搜索原生透传、403 停用、6 小时复查、成功恢复、状态持久化和页面账号选择。完整离线 Go 测试、go vet、305 项 UI 测试及真实 Chrome 宽窄布局与交互检查均通过；当前机器缺少 CGO C 编译器，未执行 Go race。
