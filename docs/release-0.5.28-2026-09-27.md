# 0.5.28：账号名称、设备收敛与可靠性加固

日期：2026-09-27（UTC+8）。插件 ID 保持 local.oai-basispoints，签名身份沿用 oai-basispoints-v1 和原 Ed25519 公钥。

## 本次修复

- 账号主标签恢复完整名称，次级完整 ID 区分同名账号，无名称回退 ID；检测和保存继续按数字 ID 对应。修复账号改名后列表与检测摘要不刷新、结果 ID 被截断的问题。
- 新增“设备收敛”开关 bps_device_convergence，默认关闭，保存并读回确认后生效。开启后优先使用宿主 openai_device_id，其次按官方 codex_fingerprint_seed 算法派生；旧宿主从已解析的上游账号身份稳定派生。普通转发、图片附件、重试、工具纠正和检测沿用同一设备身份，保留原有会话边界。
- 设备缓存复用目录刷新和失败退避；缓存命中按账号 ID 做 O(1) 查询，避免每请求复制／扫描整份账号目录。换宿主、关停和刷新不会保留错误世代的缓存。
- **发现并修复 429 漏网**：HTTP 200 的 JSON／SSE 错误中，insufficient_quota、usage_limit_exceeded 和宿主识别的自然语言配额错误此前可能未经隔离进入宿主限流处理。本次对齐官方宿主规则，只检查失败诊断，不扫描正常答案或工具参数。24 种回归组合中的 20 种问题已复现并修复。
- 明确 BPS 403 仍仅停用当前账号的 BPS，默认开启的“403 自动停用”开关可关闭。补充重复流式错误只持久写一次、旧恢复确认与新 403 并发时不能清掉最新封禁的回归。关闭开关不会恢复既有停用，需明确重新勾选账号并保存。
- 单账号检测使用目标账号自己的身份与代理，结果不串号。修复不确定／否定答案误判、混合代际、多输出矛盾、success:false／ok:false／HTTP 错误信封及 SSE event:error 被 completed 载荷覆盖的问题；含糊回答保留原文但不参与分类或自动选择。
- 修复超大正数 Retry-After 溢出导致提前重试的问题；长等待保留原响应，不自动重试 429，不重复已开始的流。
- BPS 转发与检测拒绝 HTTP 301/302/303/307/308 重定向，避免身份头、设备字段和正文被自动转发给重定向目标。复用原连接池、代理和超时，不改变宿主原生透传。

## 可靠性边界

- 429 隔离的含义是防止 **BPS 错误污染宿主 Codex 账号状态**。BPS 本身仍可能限流；原生透传的 Codex 429、宿主自身配额／并发限制仍按原规则处理。
- 403 停用的重启持久性依赖宿主 KV 可用；写失败时插件内存停用、重试并显示错误，不能在 KV 长期不可用时保证跨重启保存。账号仍存在于宿主，取消 BPS 后后续请求按原生路径处理。
- 检测仍是原有固定“17”代际规则；明确其他代际会标为疑似降智。该规则不验证最新手机发布情况，不是可靠的通用智力测评，也无法证明上游模型身份。
- 设备收敛确实改写已知载体，但不隐藏认证信息，不改变出口 IP／代理／TLS 指纹，不处理任意嵌套用户文本，不能保证服务端风控结果。关闭开关不代表不上传设备信息，也不能撤销宿主的改写。完整范围见 [设备指纹说明](BPS-DEVICE-FINGERPRINT.md)。
- 若宿主已做 session/full 收敛，插件无法还原原始会话标识。要保留各客户端会话，应将宿主设为 device 或 off，再按需启用本插件设备收敛。
- 本次未调用真实 OAuth/BPS 账号、未消耗检测额度，未部署至生产服务器；本地模拟、真实宿主进程测试与线上验收是不同范围。

## 覆盖安装

1. 在 Sub2API 插件管理页先停用旧插件及其绑定。
2. 上传本次相同插件 ID 的签名安装包；原 trusted_publishers 公钥无需更换。
3. 官方 0.2.8 保留原插件加密配置及 KV，因此原模型／账号选择和 403 停用记录保留；新增设备开关缺省为关闭。
4. 更新会重建绑定，状态为停用、灰度比例为 100%。先重新设置所需灰度，再启用插件和绑定。
5. 重开配置页，确认运行版本 0.5.28、完整账号名称和两项开关，保存并读回确认。
