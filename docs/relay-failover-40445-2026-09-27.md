# 错误 #40445：工具协议失败被误判为上游不可用

报告时间：2026-09-27 14:28:49。请求 ID：c5db9aab-fb46-442d-8857-f375d6b7c0c9。

## 已确认的问题

日志中原始失败为 invalid_tool_call / malformed or ambiguous client tool relay
envelope。宿主记录 kind=failover，客户端却收到 upstream_error / Upstream
service temporarily unavailable。这能确认错误被宿主转换，不能仅据此断言
发生了网络断开，也不能确定原始 arguments 具体违反了哪项封装规则。

插件在流已经开始后，使用 response.failed 结束工具校验错误。此前该错误
仅有 code 和 message，缺少 type。Sub2API 0.2.8 的
openAIStreamFailedEventShouldFailover 对未匹配排除条件的 response.failed
默认返回 true；response.created 等非语义事件尚未阻止换号时，会进入
failover，最终把诊断改成通用 502。

## 本轮修复

- 为插件生成的 invalid_tool_call 流式终态添加 type=invalid_request_error，
  保留原 code 和安全 message，使用宿主已有的请求级失败分类。
- 不执行无效调用；不通过额外换号来重放整轮请求。既有单次、未执行末尾工具
  的纠正流程保留。
- 网络、EOF、超限等错误不被泛化为请求级错误。未发送响应字节的 RPC 错误
  继续保留 RequestSent=true，不改变既有宿主禁止重放的契约。
- 本次修复位于插件内部，无需修改宿主生产源码。

这项修复解决误换号及错误遮蔽；不能让真正有歧义的工具参数变成合法输入。
同类封装恢复改进见 relay-envelope-40375-2026-09-27.md。
