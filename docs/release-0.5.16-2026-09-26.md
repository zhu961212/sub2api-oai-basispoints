# 0.5.16 自动原生图片附件

日期：2026-09-26（本地日期）。插件 ID：local.oai-basispoints。

## 直接发送图片

客户端直接发送图片或截图，插件自动调用 BPS 原生附件接口，再把返回的 file_id 交给同一个 gpt-6-astra 对话。消息、function 工具结果和 custom 工具结果中的图片都支持。上传与后续对话共用宿主本次调度账号的凭据和代理。

配置页删除图片中转开关、公网地址、监听地址及存储目录，仅保留账号选择和直接发图说明。升级时四个旧 image_relay_* 字段自动规范化清空；不启动图片监听、不生成公网图片链接、不将图片写到本地文件，也无需增设反向代理。

PNG/JPEG/GIF/WebP 原图保持字节、尺寸和可支持的 detail。有效 file_id 与已有 HTTPS 图片引用继续可用；detail=original 仍明确拒绝。

## 性能与边界

- 使用流式 multipart 上传原始图片，避免额外完整解码副本及本地图片文件。
- 同请求重复图片只上传一次；跨请求仅在可信会话、账号、令牌和端点相同的条件下复用附件 ID 元数据，最多 512 项、最长 30 分钟。无可信会话标识时不跨请求复用。
- 30 分钟是本地缓存上限，不是对上游文件保留或删除时间的承诺。
- 单张最多 20 MiB、请求最多 20 次内嵌图片、解码后总计 32 MiB，单张最多 64 × 1024 × 1024 像素；重复图片每次出现仍计入图片数量和总量限制。
- 完成原请求读取及 JSON 解析后，才对内嵌图片工作应用 64 MiB JSON、32 个并发请求、512 MiB 估算预算准入。该预算不限制初始读取缓冲，也不是进程 RSS 的硬上限。
- 上传失败不再继续发送 Responses 请求；保留适用 HTTP 状态码，错误提示不暴露图片内容，原生文件 ID 和旧图片链接令牌均脱敏。
- 会话与回合标识先根据原始历史生成，重新上传得到不同文件 ID 时，同一回合的工具续接仍保持 task_id / turn_id 和正确的迭代次数。
- 共享上传的发起者取消时，仍有效的等待者最多用自己的上下文接管一次；普通上游错误不自动重试，避免把一个请求的取消传给另一个正常请求。

0.5.15 性能数字仅属于旧自托管路径，历史 [性能记录](PERFORMANCE-0.5.15.md) 保持原样；本次没有将它们作为原生附件上传或真实识图速度的证明。
