## 可复现的插件问题与修复

1. 动态发现的 additional_tools / 已完成 tool_search_output 原先被全部合并到请求开头的工具目录。每发现或更新一个工具，之前的长对话前缀都会变化。现在在客户端显式提供顶层 tools 时保留初始目录，把动态声明作为 developer 目录更新放在原来的历史位置。最终提醒与响应校验仍使用完整、本轮冻结的有效工具目录。
2. 历史工具已从当前目录移除或变成冲突声明时，缓存的原生调用会被误判为不匹配，重新构造的封装改变旧历史。现在名称精确匹配的历史数据仍可重放，继续核对 call ID、已有 item ID 和完整参数；新工具调用仍按当前目录授权，不能借历史记录恢复已撤销权限。

完整历史、工具结果、工具描述、schema、自定义 grammar 和缓存 usage 均保留。不新增上游请求、不扩大会话权限、不引入新的跨请求目录缓存。

## 边界

- 缺失显式顶层 tools 时仍保留现有目录继承规则；无法可靠推断最初目录，不能承诺该模式的发现前缀稳定。
- 客户端改动顶层工具、instructions、历史正文、模型或推理设置时，仍可能导致缓存失效。
- 原生工具历史仍受既有 512 项、32 MiB、2 小时闲置限制；淘汰、重启、换账号或缺少可信 conversation_id 时，精确原生封装可能不可用。此次未通过无限增加缓存或放松会话隔离来掩盖边界。
- 上游自身的缓存路由、保留时间和实际返回用量不能由插件强制控制。本地回归证明消除了上述可复现的前缀改写，不证明生产命中率已恢复到 93%。
