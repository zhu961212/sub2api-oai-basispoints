报告中的 invalid_tool_call / response.failed 表明代理未能还原工具封装；

因此本记录修复的是本地复现的同类错误，不能断定生产请求属于其中某一种。

## 修复内容

- 外层 run_officejs arguments 原先只接受严格 JSON，而内层 code 已支持恢复
  字符串内的裸换行、制表符和非法反斜线转义。现在外层采用相同的字符串修复，
  随后仍要求完整、无重复键的严格 JSON；不会从任意文本中抽取外层调用。
- 完整 JSON 字符串包装内的已知截断调用，原先无法进入一次上游重生成流程。
  现在最多解开三层完整字符串包装，再严格识别内部截断对象，与现有四层
  code 解码预算一致。未完成的包装字符串本身不被猜补。
- 合法转义、工具原始输入、大整数和重放身份保留。重复键、多候选、冲突字段、
  过深包装仍然拒绝。截断内容不执行、不写入重放缓存；既有历史完整性检查、
  单个末尾未执行工具限制及最多一次纠正保持不变。
- 集成测试发现 JSON 响应转为合成 SSE 时，自定义工具 input.done 会裁剪输入
  首尾空白。已改为保留原始字符串，同时为空字符串发送对应的完成事件。

## 最小复现

- 新增 relay_outer_syntax_test.go：四种外层字符串语法在修复前均产生报告中的
  malformed or ambiguous 错误，修复后通过；同时覆盖 code 对象、原始输入、
  大整数、四层解包预算和重复键/截断/多对象拒绝。
- 新增 relay_quoted_repair_test.go：截断字符串/对象在一至三层完整包装下，
  修复前失去纠正资格、修复后恢复；未知工具和歧义输入仍拒绝。
