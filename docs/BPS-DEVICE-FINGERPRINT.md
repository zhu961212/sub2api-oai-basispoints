# BPS 仅设备指纹收敛

自 0.5.28 引入，默认关闭；此说明描述插件可验证的字段改写范围，不代表上游风控保证。

## 行为

启用设备收敛后，经过 BPS 的请求采用 Sub2API device 模式的设备收敛语义：同一账号的不同客户端使用同一个安装／设备标识，账号之间各自独立。仅改变设备身份，不将会话、线程、窗口或请求 ID 合并为账号级常量；不主动采集客户端 MAC、硬盘或浏览器硬件指纹。

配置页提供“设备收敛”开关，对应 bps_device_convergence，默认关闭；旧配置未设置此字段也按关闭处理。点击后显示待保存，保存并读回确认后生效，重新打开页面保留已保存状态。保存和检测期间锁定开关，检测临时配置及收尾保留它的值。

启用时对 BPS 转发及单账号／批量检测执行同一策略；关闭时插件停止改写设备请求头和正文设备字段，也不为请求查询设备元数据。关闭不等于删除设备标识，不会撤销宿主已经做过的指纹改写。单次请求头和正文始终使用请求开始时同一配置快照，中途切换只影响新请求。未选模型、未选账号等宿主原生透传分支不应用。

## 设备 ID 来源

1. 优先读取宿主账号目录 metadata_json 中 Extra.openai_device_id（支持顶层 Extra / extra）。
2. 没有有效显式设备 ID 时，读取 Extra.codex_fingerprint_seed，要求规范小写且非零的 UUID；使用与 Sub2API 相同的 SHA-256 派生算法和 UUIDv4 格式，命名空间为 sub2api:codex-install-id:v2:。
3. 旧宿主、不在可读目录中的账号或暂时无法读取账号元数据时，从实际认证的 ChatGPT 账号 ID 派生稳定 UUID，命名空间为 sub2api:bps-install-id:v1:。不使用客户端 installation_id、本地数字账号 ID 或 access token 作为种子。

启用插件开关后，显式配置及派生算法与宿主保持一致，不依赖宿主 codex_fingerprint_mode 的 opt-in 门控。旧宿主兜底是公开账号身份的确定性派生，并不等价于宿主随机种子；同一上游账号在不同部署上的兜底 ID 相同。它跨插件重启、升级和 token 刷新保持稳定，不需要额外 KV，也不写回宿主账号配置。

账号元数据复用现有 5 秒缓存，设备热路径按数字账号 ID 做 O(1) 索引查询，避免复制和遍历整份目录；短暂刷新失败保留已有快照。首次目录不可用时使用兜底，恢复读取到宿主设备配置后可能切换一次；管理员更换设备 ID／种子后也会在缓存刷新后生效。只缓存最终设备 ID，不保留整份账号元数据或种子，不在 Health／配置页面输出设备值。

## 改写范围

- 请求头固定 X-Codex-Installation-Id，已有的设备／安装 ID 常见别名同步成单值，去掉同名多值中的旧设备。
- 已存在的 X-Codex-Turn-Metadata JSON 中只更新设备字段；会话、线程、turn、窗口等其他字段保留。字符使用 HTTP 安全的 JSON 转义；损坏的 JSON 重建为仅含安装 ID 的最小对象。
- 请求体只处理根对象、metadata、client_metadata 中已存在的设备字段，以及其内嵌的 x-codex-turn-metadata 对象／JSON 字符串，不扫描或修改用户消息、工具参数和工具结果。
- 不为 BPS 正文新增 metadata／client_metadata 容器；仍遵循原有 BPS 协议转换。rewrite_tools=false 且无图片时也执行必要的设备字段改写，不会直接透传原始设备值。
- 普通转发、附件上传、HTTP 重试、工具纠正和主动账号检测复用同一个设备准备入口或已准备的请求。

## 会话边界

本改动不扩大原有 BPS 请求头白名单，不改变原有 task_id／turn_id 派生和图片缓存会话隔离。原本只在本地使用的 session-id 等头，以及默认工具转换会丢弃的 client_metadata，仍按既有协议处理。这里的“仅设备”指只收敛设备，不能理解为仅上传设备字段或不再发送认证、任务和会话信息。

如果宿主账号已经启用 session/full 收敛，插件接收到请求时原始会话标识可能已经被宿主覆盖，无法恢复。需要保留各客户端会话时，将宿主账号的指纹模式设为 device 或 off；开启插件“设备收敛”后，为命中 BPS 的请求执行 device 收敛。

## 验证

回归覆盖默认关闭、显式开关及序列化、开启→关闭→开启、处理中切换配置快照、关闭不额外读取设备目录、页面保存与重开、保存回包／读回不一致、检测临时配置保留，以及宿主设备优先级及种子算法、账号隔离、不同客户端／token 刷新／重启稳定、多个设备载体同步、JSON 字符安全、默认转换及关闭工具转换、附件／检测一致性和非 BPS 透传。测试使用本地模拟宿主／上游，不访问真实 BPS，不消耗账号额度。

离线命令：go test ./... -skip TestLive -count=1 -timeout 120s；go vet ./...。

## 可靠性边界

上述回归可验证字段确实被改写，以及账号、开关、配置快照和缓存生命周期保持隔离；不能证明 BPS 服务端如何使用这些字段。它不隐藏账号认证信息，不改变出口 IP、代理或 TLS 指纹，也不承诺消除 403／429 或服务端风控。任意嵌套用户内容不会被当作设备元数据清洗。BPS 转发和检测拒绝重定向，避免将身份头和正文自动转发给另一个目标。
