# 0.6.8：原生降智检测空文本修复

日期：2026-09-27。插件 ID 为 local.oai-basispoints；本地修复包，尚未发布到 GitHub 或部署到服务器。

最终确认：降智检测只请求原生 Codex，固定 gpt-6-astra + XHigh；不需要 BPS 检测。临时 BPS、ultra/max 对比测试入口已移除，以下对比数据保留为历史记录。

## 已确认原因

用户提供测试账号后，通过该账号导出文件中关联的代理请求原生 Codex，确认两处问题：

1. 原生 SSE 在 response.output_item.done 中返回了完整 assistant 消息，但最后的 response.completed.response.output 是空数组。旧检测器只取最后的 response，导致已有答案被丢弃并显示 upstream response contains no output text。
2. 旧探针及宿主默认的 Codex 0.146.0 身份被 gpt-6-astra 拒绝，上游返回 HTTP 400，说明该模型需要更新的 Codex 版本。

## 修复

- 保留完成的 assistant 消息快照，仅在成功的响应终态缺少答案时使用。按输出位置排序、按消息身份去重；冲突、失败、未完成、拒答、推理和工具文本不能被当成有效检测答案。
- 仍要求响应成功完成；收到消息完成或部分增量不会提前给账号判定。完成事件到达后立即返回，不等待连接 EOF；原大小限制和超时继续生效。
- 插件生成的原生探针统一使用已实测的 0.158.0-alpha.2.1 客户端身份，匹配本机已安装的 Codex 版本；不继承旧宿主的客户端版本头。账号凭据、账号 ID、关联代理仍由宿主提供。正式业务请求不受此探针身份修改影响。
- 按用户要求，三个检测入口固定使用 gpt-6-astra + XHigh（reasoning.effort=xhigh），问题不变。自动模式不会把升级前 low 的待确认结果与 xhigh 累加；已有有效路由保留，切换仍需要新的两次确认。
- 失败、跳过不自动启用 BPS；account is not schedulable 仍表示宿主当前不允许调度该账号，不能当作模型检测结果。

## 验证与边界

- 修复后，同一测试账号及关联代理通过实际检测入口 TestLiveDegradationRunner 实测：low 返回 iPhone 15 Pro Max，8.212 秒；改为 xhigh 返回 iPhone 16e，8.525 秒，均正常完成。按既有固定“17”规则，两个答案都属于疑似降智，检测成功不等于账号通过规则。单次结果不同不能证明思考程度造成差异。
- 此前两次 low 脱敏跟踪均返回 HTTP 200，完成项回答 iPhone 16e，而完成响应的 output 数组为空，直接证实了流式答案丢失的路径。
- 用户随后要求比较 BPS：同一账号、同一代理、同一问题，经过插件实际 BPS 请求构造发送 gpt-6-astra + reasoning_effort=xhigh，HTTP 200，回答 iPhone 16e，9.931 秒，与原生 XHigh 本次回答相同。比较测试单独显式启用，不改变正式原生检测入口。
- 用户进一步确认使用最高思考程度后，同参数再次请求 BPS，并校验响应 reasoning.effort 确实为 xhigh：HTTP 200，回答 iPhone 17 Pro Max，15.219 秒，符合当前“17”规则。前一次同参数为 iPhone 16e，因此这些单次结果存在波动，不能据此推断思考程度发生变化或账号能力已稳定恢复。max/ultra 在本插件中也映射为 xhigh。
- 测试期间关联代理有间歇性连接重置，属于独立的网络失败；不把这类失败算作降智，也未加入自动重复扣额度的网络重试。
- 流解析回归覆盖稀疏完成响应、分块、终态别名、EOF、失败与截断、非 assistant 内容、重复/冲突快照及终态拒答。客户端身份回归覆盖旧宿主头以及单号、批量、自动三个入口。
- 测试账号仅验证其自身；不能据此断言报错列表中的其他账号均已通过，也不能确定 #198 不可调度的具体原因。
- 不保存测试账号凭据或完整原始响应。发布或安装后应在宿主中重新检测相关账号。
