# 缓存与上下文策略

交流群：**1107265919**。

本文区分上游 prompt cache 的路由提示与插件进程内的上下文、连接池及附件缓存。插件只能修正自身的转发与统计行为，实际命中量仍由上游返回。

## 2026-09-30 缓存路由与用量回归

本轮为本地源码修复，无需新增宿主补丁；尚未打包或部署。

- 修复只有可信会话头、没有正文缓存键时的提示丢失：BPS 请求使用调度账号 ID 与宿主已隔离的 conversation_id 生成稳定、不可读的 prompt_cache_key。同一会话追加历史、执行工具或修改逐请求元数据不会重新生成不同的键。
- 显式 prompt_cache_key（含已支持的 promptCacheKey 别名）继续原样优先。没有可信会话或会话头冲突时不从相同开场白、正文 session_id、共享账号指纹推导缓存键，保持现有会话隔离边界。
- 缓存提示不授权工具回放，也不替代完整历史。工具目录稳定排序和历史原生调用重放沿用原有逻辑。
- “写缓存”来源于上游返回的真实缓存创建字段。不会将它清零、改成命中数，或根据本地请求相同就伪造缓存命中。JSON/SSE 转换保留读写缓存、明确的零值及未知用量字段。
- 工具纠错若实际触发第二次推理，两次真实用量分别计入一次；重复的 SSE 生命周期快照不重复相加。

离线回归覆盖缓存键跨轮次稳定、跨账号/会话隔离、头冲突与伪造正文标记、完整工具对话的请求前缀和原生调用重放，以及 JSON/SSE 四种转换组合的读写缓存计量。尚未做真实上游命中率对比，不能据此承诺生产命中率提升幅度。

## 2026-09-27 缓存隔离与上下文失效修复

本轮修复纳入 0.6.5；最终签名产物、CI 与上传验证以 0.6.5 发行记录和 Release 为准，不代表生产部署。

- 宿主账号指纹可能把 session_id 收敛成账号级固定值。工具目录、原生调用回放和响应映射现在只使用宿主按 API key 隔离的 conversation_id，并加上本次调度账号 ID；不同对话或账号不再因为共享 session_id 而复用上下文。
- 缺少可信 conversation_id，或同一请求头存在冲突值时，禁用跨请求上下文缓存；请求正文中的 session/conversation 别名和响应编号不能重新启用它。图片缓存使用相同的可信请求头解析规则。
- 禁用缓存不删除当前请求的完整历史、工具结果或工具声明。客户端应继续携带完整历史和所需目录；previous_response_id 仍不替代历史，也不新增服务端长期会话存储。
- 已准备的会话请求完成时只登记响应映射，不再补写已失效的目录。即使新目录或撤销标记已过期、被淘汰，迟到响应也不能恢复旧工具；新的显式请求仍可正常更新目录。
- 请求改写和仅响应转换两种模式都在发出请求前冻结工具目录；同会话后续更新不会改变在途响应的校验依据，迟到响应也不会覆盖较新的声明。
- 缓存键与字符串值单独持有自己的存储，避免短字符串保留超大原始缓冲区。typed containers 和 custom marshalers 的 JSON 回退路径也执行快照内存预算检查，与标准 JSON 树路径一致；最终缓存写入的容量上限保持不变。

验证：完整 Go 回归（go test ./... -skip TestLive -count=1 -timeout 120s）、go vet ./... 和 git diff --check 均通过。新增回归覆盖跨会话/跨账号隔离、无可信作用域的完整历史、目录淘汰后的迟到响应、字符串存储所有权、类型化快照预算，以及仅响应转换下 JSON/SSE、显式/继承目录、更新/撤销共 8 组并发场景。本机 CGO_ENABLED=0 且无可用 C 编译器，未执行 race；未连接真实上游。

## 2026-09-27 本地源码优化

本轮修改已通过本地回归，尚未打包、发布或部署。

- 工具目录按完整工具名稳定排序，完全重复的声明只输出一次；同一集合乱序不再改变请求上下文。冲突声明继续拒绝调用，同时从目录和尾部可调用列表移除。完整工具描述、schema 和 custom grammar 保留。
- 请求准备时从冻结目录构建只读工具索引，历史翻译、响应校验和工具修复复用同一索引；显式 tool_choice: none 仍优先生效。索引仅存活于当前请求，不增加全局会话缓存。
- 标准 JSON 树入缓存时一次遍历完成复制、编码长度检查与内存计重，提前拒绝超额内容；精确数值及字符串存储隔离保留。typed containers、custom marshalers、无效 UTF-8 和深层结构保留原 JSON 规范化回退。
- 图片缓存合并命中检查与并发上传登记的锁；未满时不扫描无关条目，满容时一次遍历完成过期回收和 LRU 选择。过期 ID 在读取时立即失效，未访问的过期元数据可保留到容量回收，总量仍最多 512 条。
- 修复上游直接工具调用缺少 call_id 时，生成编号后误覆盖已包装 relay 的问题；function/custom 两类调用的后续仅结果回合都能恢复正确的原生调用。

完整历史、会话隔离和压缩阈值沿用现有语义，不按重复文本裁剪历史，也不删除历史图片或工具结果。

## 缓存边界

| 缓存 | 上限与过期 | 隔离、更新与回收 |
| --- | --- | --- |
| 原生工具历史 | 512 项 / 32 MiB 估算预算 | LRU；2 小时闲置过期；按调度账号、可信会话及 call ID 隔离 |
| 工具目录 | 256 项 / 32 MiB 估算预算 | LRU；2 小时闲置过期；按调度账号及可信会话隔离，增量更新原子合并 |
| 响应上下文 | 512 项 / 1 MiB 估算预算 | LRU；2 小时闲置过期；响应 ID 映射到隔离会话；无可信会话不登记 |
| 图片附件 ID | 512 项 / 上传起最多 30 分钟 | 完整内容+MIME+可信会话+账号凭据+端点的带密钥摘要；命中不续期 |
| 账号代理连接池 | 128 项 / 5 分钟闲置 | 完整代理 URL（包括凭据）隔离，LRU，淘汰只关闭空闲连接 |
| 账号目录 | 成功后 5 秒；失败退避 1 秒 | 并发共享一次最多 3 秒的刷新；已有快照立即返回；冷请求可独立取消 |

工具历史和目录的单条估算上限为 4 MiB；响应上下文单条上限为 16 KiB。预算包括内容和容器元数据估算，不是进程 RSS 或在途请求的硬上限。过期清理在后续访问时触发，不新增定时清理线程。

超大工具目录不长期缓存，显式更新会清除旧目录并保留空标记，避免旧工具恢复。缓存过期或被淘汰后，客户端应携带完整历史和所需工具目录；缓存不充当长期会话存储。

## 已修复的问题

- 原 FIFO 淘汰会清除持续使用的会话；现在按最近使用淘汰。
- 原工具历史缓存 JSON 转换会把大于 2^53 的整数变成浮点数；现在保持精确数值。
- 全局锁内反复序列化/解码会阻塞其他会话；现在只在锁内获取不可变快照，锁外复制容器并复用不可变字符串。
- 任意新代理永久增加连接池；现在有容量和闲置边界，淘汰不打断活跃请求。
- 保存账号或工具配置曾重建全部连接；现在只有网络超时设置变化时重建。
- 账号列表刷新曾持锁等待宿主 RPC，失败后连续重复查询；现在合并刷新、独立取消、失败退避。宿主重连/关闭会使旧结果失效。
- 缺少可信会话的图片请求原来写入随机作用域缓存，内容永远无法复用却会挤走有效条目；现在只做请求内去重，不写持久图片缓存。
- 重复图片原来多次计算完整摘要；现在同请求先识别相同内容。跨请求仍校验完整 HMAC，缓存未命中时仍严格检查 Base64、格式和尺寸，不降低校验。
