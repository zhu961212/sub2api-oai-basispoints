# 0.6.1：全选反馈修复与请求快照账号检测

> 历史方案：0.6.1 已撤回。0.6.2 改用插件内检测任务，不需要该宿主补丁或重建 Sub2API。当前版本也已移除设备收敛功能及配置开关。以下保留当时的实现与验证记录，不代表当前能力。

日期：2026-09-27（北京时间，UTC+8）。插件 ID 保持 local.oai-basispoints，签名沿用 oai-basispoints-v1 和原 Ed25519 公钥，不需要替换宿主受信发布公钥。

## 更新内容

- 全选当前列表后显示“已全选列表账号”，不再仅因已全选而置灰；加载、保存及检测期间仍锁定操作。
- 配套宿主增加 config.testScoped，将本次账号和配置快照直接传给 TestConfig，不保存诊断命令，不从共享配置重新读取目标。单号检测不改变账号勾选。
- 一键检测仅扫描点击时的账号目录快照，不包含其后新增的账号。存在确认的疑似降智结果时更新本地选择，失败、跳过及列表外账号保留原选择，点击保存后生效。检测规则仍为自定义“苹果17”规则，不是通用智力测评。
- 校验请求 ID、目标 ID 及逐账号结果；并发检测不持有宿主全局配置锁。二次验证过期或配置页已切换时，不再派发原来的检测。
- 扫描内部预算耗尽正确标记未完成并保留已取得结果；普通保存及回读拒绝残留批量检测字段。
- 未保存的 403 恢复勾选不能授权检测；明确 403 仍按策略只停用实际检测账号。

## 宿主兼容与升级

**恢复主动检测必须同时更新宿主前后端和插件。仅安装 0.6.1 插件不会使未修改的官方 0.2.8 获得检测能力。**

发行附件提供 sub2api-config-test-scoped-for-bps-0.6.1.zip，其中包含以宿主提交 a3eb7ef302961cba716dc78b39b93b60c467db0e 为基础的最小补丁和构建步骤。该补丁只包含本次相关的 12 个文件；未包含本地宿主仓库已有的 OAuth、发布流水线或其他未完成工作。应用方法见 [配套宿主补丁](host-patches/README.md)。补丁是需要构建的源码，不是已构建的宿主程序或 Docker 镜像。

1. 对照补丁 README 应用并构建配套宿主前后端，部署后重新打开插件管理页。
2. 停用旧插件，上传相同插件 ID 的 0.6.1 签名包，继续信任原发布公钥。
3. 按宿主流程重新设置所需灰度并启用插件。保留原模型和账号配置以及 403 停用记录。
4. 重新打开配置页以协商新能力。先确认列表和全选状态；被 403 停用的账号需明确重新勾选并保存后才可检测。
5. 单号检测只显示该账号结果；批量检测的选择变化需点击保存。

旧宿主仍保留转发、配置保存、被动状态和普通 TCP/TLS 连通性测试；主动检测继续显示升级提示，不回退到不安全的 save → test 链。普通连通性成功不代表账号 BPS 权限有效。

宿主对同一插件/request_id 在单进程内缓存结果 10 分钟，最多 256 条；相同请求不会在此窗口重复派发，冲突配置会拒绝。该保护不跨重启或多实例，UI 不自动重试检测，用户再次点击会发送新请求。
