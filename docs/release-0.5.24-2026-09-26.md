# 0.5.24：新增账号默认使用 BPS，并修复一键检测读取

## 新账号自动接入

新模式使用 `auto_select_new_accounts=true`，以 `excluded_account_ids` 保存持久排除的账号 ID。后台直接允许不在排除表中的账号，因此宿主后来新增的账号即使还没打开配置页、已保存的 `account_ids` 快照还没有该 ID，也能使用 BPS。

- 界面读取到新账号时自动勾选。手动取消并保存后，刷新、重开页面或增加其他账号不会恢复该账号的勾选。
- `account_ids` 在新模式下是界面选择快照，不是完整许可名单；显式排除记录优先决定是否接入。
- 全选列表账号会移除当前列表账号的排除记录，保留暂未显示账号的既有选择与排除记录。
- 新模式下取消所有账号并保存，会排除当前全部已知账号；未来新增账号仍默认接入。要停止全部 BPS 请求，请取消所有模型并保存，或在宿主停用插件。
- 一键检测降智账号的自动选择也同步排除表。没有疑似降智账号时保留原选择，保存失败时恢复原选择。

自动接入只作用于宿主交给插件、命中插件灰度且模型已勾选的请求。宿主仍负责账号调度、可用状态、凭据、代理、Token 生命周期、用量与计费；插件不会使未命中灰度的请求转入 BPS。

## 旧配置迁移与升级

1. 在插件管理页安装并重新加载 0.5.24，确认配置页显示运行版本 0.5.24。
2. 旧非空白名单升级后先维持原路由。打开配置页，成功读取完整账号目录、确认选择并保存一次后，才将当时未勾选的账号迁入排除表并启用新模式，尊重原来取消的选择。
3. 旧空白名单原本不限账号，因此页面显示为全选。新版界面“全不选账号”则表示排除当前已知账号，两种语义不可混淆。
4. 出现“已保存，并已重新读取确认”后，再在宿主新增账号，检查已选模型请求和手动排除账号的透传行为。模型选择和宿主灰度继续生效。

未迁移的旧配置仍兼容 `account_ids` 原白名单语义：非空只允许列出的 ID，空列表不限账号。无需修改宿主或重编译宿主。

## 一键检测读取修复

用户报告宿主账号 #274 显示 `upstream response could not be read`。检查旧实现可确认三个问题：单账号硬性预算为 8 秒、读取整个响应一直等待 EOF、不同读取错误被统一为同一条消息。它们可能使已经发送完整 SSE 回答的请求仍被误报读取失败；仅凭该消息不能确定用户实例的唯一原因。

0.5.24 将单账号预算调为 20 秒，整轮扫描预算仍为 24 秒，单账号请求同时受整轮剩余预算约束。SSE 的完成事件一到即可提取回答，不再等待连接关闭。HTTP 403/429 等错误直接呈现 HTTP 状态，不必继续等待错误响应正文。超时、取消、截断、响应过大等分别报告脱敏原因；未完成、失败或取消的回答不参与降智判断。

现有“苹果17 / iPhone 17 / Apple 17”匹配规则保留，其他有效回答标记为疑似降智。这是原有自定义筛选规则，不是通用智能测评；每次检测会消耗被测账号的请求额度，功能由按钮触发，不在后台定时运行。

本版同时保留 [0.5.23 图片协议修复](release-0.5.23-2026-09-26.md)：用户消息图片使用原生附件 `file_id`，工具截图保持 data URL，缺失或 null 的 detail 补为 auto。0.5.22 的 BPS 429 隔离、模型选择、会话隔离、凭据和代理边界继续保留。
