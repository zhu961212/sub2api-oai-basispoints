# Sub2API 0.2.11 兼容与发布验收

日期：2026-09-30。插件版本为 0.6.11，宿主推荐版本为 Sub2API 0.2.11，两者独立编号。

## 固定的官方源码

官方仓库为 Wei-Shaw/sub2api。v0.2.11 发布标签指向提交 96f4c115c9749078f90cbf210a01d39baf3f53b6；所有宿主验收须对照该固定提交，避免混用开发分支或不同版本的宿主文件。本轮同时核验用户提供的 0.2.11 本地源码。

用户本地宿主的 3,137 个 backend 文件逐一匹配该官方提交。五份插件 API 契约文件与插件内置副本一致；从 0.2.9 到 0.2.11，插件核心服务、安装签名、配置规范化、反向服务及 UI Bridge 实现无契约变化。

该官方标签内的 cmd/server/VERSION 仍写 0.2.10；实际发行版通过构建参数注入 0.2.11。验收按官方发布标签与固定提交显式传入宿主版本，不修改 VERSION 文件来制造匹配；自行编译宿主时也应正确注入发行版本。

兼容清单继续要求 >=0.2.8 <0.3.0，已测目标为官方 0.2.8、0.2.9、0.2.11，推荐 0.2.11。插件仍使用 Plugin Protocol、Transport API 和 UI Bridge v1；不通过修改官方宿主来适配插件。

## 发布前的验收范围

- 对照官方提交核验插件 API 契约、安装和签名信任、配置规范化、子进程握手与宿主反向服务。
- 通过同一个最终签名安装包，在三版官方宿主上验证实际插件子进程、RPC、多帧转发、账号身份隔离、403 开关与持久化重启恢复、429 退避无重复出站，以及错误回放。
- 将最终包、源码提交、签名公钥、宿主固定提交及验收结果绑定；宿主源文件检查前后保持一致。
- 完整源码回归、静态检查、前端及打包工具测试、Linux race 检查和双平台构建须全部通过，再上传并回读校验发布附件。

本地正式宿主验收执行 Windows amd64 运行时。Linux amd64 在 Linux CI 执行源码回归与 race 检查，并进行运行时交叉构建、签名及哈希核验；不将这些检查表述为 Linux 正式宿主部署验收。宿主测试使用本地模拟账号和上游，不调用真实账号或计费生成接口，也不代表服务器已完成升级部署。

每次发布的实际提交、最终包哈希、CI 和正式宿主验收结果见该版本 GitHub Release。此前 0.2.8 / 0.2.9 记录保留为历史依据。
