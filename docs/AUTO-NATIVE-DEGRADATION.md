# 原生 Codex 自动检测与 BPS 切换

本页描述 0.6.7 的原生检测与自动切换实现。发行包不代表已经部署或完成真实账号验收；实际发布验证见 [0.6.7 发行记录](release-0.6.7-2026-09-27.md)。

## 检测什么

手动单号、手动批量和自动检测均使用账号自己的 OAuth 凭据及其关联代理，直接请求固定的原生 Codex 地址：

~~~text
https://chatgpt.com/backend-api/codex/responses
~~~

即使该账号的正常业务已经使用 BPS，探针仍检测原生 Codex。检测不使用 BPS 的 responses_url、已选模型列表或请求体转换，也不跟随 HTTP 重定向。原生检测模型由 degradation_check_model 独立设置，默认 gpt-5.4；修改正常业务的 BPS 模型选择不会更换探针模型。

判定仍沿用固定问题“不联网，不猜测，直接说出你知道的最新苹果手机。只输出手机型号，不要解释。”及“苹果17 / iPhone 17”规则。这是固定启发式路由辅助，不是通用智力测评，也不会自动追踪新手机型号。含糊、冲突、截断或失败回答不作为明确降智或恢复依据。检测会发送真实请求并消耗账号额度。

## 配置与开启

配置页的“原生 Codex 降智检测”区域提供以下设置；修改后必须点击保存：

| 界面设置 | 配置字段 | 默认值与范围 |
| --- | --- | --- |
| 自动检测与切换 | auto_degradation_enabled | false，默认关闭 |
| 常规检测间隔（分钟） | auto_degradation_interval_minutes | 30，整数 5–1440 |
| 原生检测模型 | degradation_check_model | gpt-5.4，非空且不含空白或控制字符，最多 128 字节 |

自动开关与“403 自动停用”开关独立。页面标记“待保存”时，后台仍按已保存设置运行；关闭页面不会停止已启用的后台检测。

## 定时与确认规则

定时按每个账号的到期时间安排，而非要求整点执行：

1. 初次检测或发现新账号时，将首次到期时间分散在约 5–30 秒后。没有有效判定的账号继续使用原有选择。
2. 稳定状态按常规间隔检测，默认每 30 分钟一次。
3. 首次出现待确认的“疑似降智”或“符合检测规则”时，保留当前路由，约 5 分钟后复测。两次连续有效结果一致，才确认切换。确认必须是同一检测模型、同一账号选择基线，且两次检测间隔不超过 10 分钟；超出窗口重新累计。
4. 连续两次疑似降智后启用该账号的 BPS；连续两次符合规则后取消该账号的 BPS，后续业务沿宿主原有上游。路由决定成功写入插件 KV 后才生效。
5. error、skipped 或尚未检测均不改变有效路由。错误清除本轮连续确认计数，通常约 5 分钟后再检查；宿主不可调度的账号不会被主动探测。

5 分钟复测间隔和两次确认阈值是当前固定规则，不随常规间隔改变。保存配置、宿主繁忙、手动任务占用或网络耗时会使实际开始时间晚于计划时间，因此界面的“下次”是调度到期时间。

自动检测按到期时间排序，每批最多 8 个账号，并发不超过 8，每批扫描预算为 24 秒，单账号请求预算最多 20 秒。24 秒限制针对自动批次，不是整个账号目录；大目录分批继续处理，优先处理较早到期的账号，避免末尾账号长期得不到检测。

自动检测与手动检测不会同时发送探针；已有手动任务时自动调度等待，自动批次运行时手动提交可能收到忙碌提示。多个运行实例之间没有分布式执行锁，当前仍按单实例使用。

## 界面与手动操作

- 自动模式下，列表显示后台实际有效路由、最近结果、复测进度和下次计划时间；账号手动勾选及全选被锁定。状态未加载完成时显示待同步，不用旧的选择快照冒充当前路由。
- 单号“降智检测”始终只显示结果。自动模式下，“一键检测原生 Codex”也只显示结果，不直接改选，不替代自动调度的两次确认。
- 手动模式下，批量检测的完整可信结果可以更新页面勾选：疑似降智勾选，符合规则取消，失败、跳过及列表外账号保留原选择；仍需点击保存才能改变路由。
- 关闭自动并保存会停止后续调度、取消在途自动探针，并保留最后一次有效路由，不会立即将全部账号切回原生。之后可手动重新选择账号并保存；即使重新选回较早使用过的组合，也以这次手动保存为准。

启用 BPS 的决定只改变账号是否使用 BPS。正常业务仍必须满足模型选择和宿主插件灰度；未勾选模型、其他模型以及未命中灰度的请求继续按既有规则处理。无有效自动决定时，账号的基础选择沿用 account_ids、auto_select_new_accounts、excluded_account_ids 的现有语义。旧空白名单仍表示“不限制账号”，不能将它解释为“全部取消”。

## BPS 403 的边界

BPS 403 停用保护优先于自动启用决定。已经被 BPS 403 停用的账号仍可以接受原生检测，但自动结果不会解除 BPS 封禁；原生检测自身返回的 HTTP 403 或流内 403 只算检测失败，不会生成 BPS 停用记录。

如需恢复已有 BPS 停用记录，应先关闭自动并保存，再明确重新勾选该账号并保存。关闭“403 自动停用”只阻止新停用，不自动恢复旧记录。恢复后再次收到 BPS 403，开启的保护仍会重新停用 BPS。

## 持久化与重启

自动状态保存在宿主提供的插件 KV 的 native_degradation_v1 命名空间，包括账号索引、有效路由、上次结果、连续确认和下一次到期时间。插件重启后读取这些记录，恢复有效路由与周期调度；它不依赖配置页持续打开，也不靠修改生产配置来写回每次结果。

每次上游请求前先持久化在途状态，防止重启后立刻无条件重发旧探针。不确定或中断的旧请求不会作为新的确认结果；后续按恢复后的调度继续。关闭自动后的有效路由仍可从 KV 恢复，直到用户手动保存新的账号选择。

KV 不可用或记录损坏时，不假定状态为空、不凭失败切换路由，并显示状态异常；状态尚未加载时也不会短暂采用过时的手动路由。已保存状态的可恢复性依赖宿主 KV 的持久性，当前没有跨副本的“恰好一次”保证。

手动任务使用单独的 diagnostic_jobs_v1 协议与消费记录。手动任务重启后不自动重跑，与自动周期恢复不是同一种行为，详见 [手动检测任务协议](PLUGIN-DIAGNOSTIC-TASKS.md)。

## 验证范围

本地回归通过合成账号、模拟 RoundTripper、本地 HTTPS CONNECT 代理验证请求原生地址、账号和代理隔离、重定向拒绝、403 隔离与调度状态。普通回归不应向真实原生或 BPS 账号发送请求。真实原生测试额外要求显式设置 BASISPOINTS_LIVE_NATIVE_DEGRADATION=1，再提供专门授权的测试凭据；仅存在旧 BPS 测试凭据不会授权这项探针。

发布验证区分最终签名包宿主验收和同一提交的原生诊断测试构建：原生诊断仅在独立的 loopback 源码覆盖构建中执行，正式包不包含测试端点。实际结果及 CI 链接记录于 GitHub Release；自动切换与时区的网络回归使用模拟传输，源码测试不等同于真实账号效果验证。
