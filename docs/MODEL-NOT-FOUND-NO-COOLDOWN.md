# model_not_found 不再触发限流／冷却

日期：2026-09-30。纳入 0.6.10，发布附件及最终验证结果见对应 GitHub Release；发布不代表部署服务器。

## 问题与修复

请求返回 HTTP 404，错误码为 model_not_found。宿主会将该响应作为账号／模型不可用信号，写入 30 分钟模型冷却。报告中的原生透传也会走这条路径。

插件现在在发送 HTTP 响应头和正文之前，将已确认的这类错误转换为 PLUGIN_MODEL_NOT_FOUND 插件错误，并设置 request_sent=true。宿主保留该次请求失败和诊断，但不进入账号／模型限流、临时禁调或跨账号重放路径。该次错误附带的配额头也不会写入账号状态。

此规则同时覆盖 BPS 与宿主原生透传；支持 JSON 和 SSE 错误体、流式与非流式客户端，以及 detail.error.error 等网关嵌套。只检查错误信封中的明确错误码，不匹配普通输出或工具参数里的同名文字。探测沿用 64 KiB 有界读取，并保留不匹配响应的原始字节和读取错误。已有工具错误分类保持有效。

HTTP 401、403、429、其他 HTTP 状态和未确认的 404 继续采用原处理。此次修改不自动清除宿主此前已保存的冷却状态，也不使上游原本不可用的模型变为可用。安装包含本补丁的插件并重载后，后续命中此规则的错误才会被隔离。

## 验证

- 新增转发回归在修复前复现失败；修复后原生透传／BPS、JSON／SSE、流式／非流式组合全部通过，且同账号后续请求成功。
- 边界测试覆盖深层错误信封、无关 404、真实账号错误冲突、普通输出、过大或损坏正文、读取失败、SSE 终态及时结束和已有工具失败标记。
- 在本地宿主 0.2.8 源码上使用只读 Go overlay 验证：原始 404 写入模型冷却；插件错误帧经过真实 gRPC runtime 和两条宿主转发错误分支后，不换号、不写账号／模型限流、临时禁调、错误状态或 Extra，连续请求不产生运行时禁调。未修改宿主生产源码。

可复现命令（宿主路径按本机调整）：

    go test ./...
    go vet ./...
    python tools/host-relay-integration/run.py --host-source E:/sub2api --suite model-not-found

最后一条使用本地合成请求，无需账号凭据、数据库或生产服务。它验证本地宿主代码契约，不代表已连接生产服务器验证或部署。
