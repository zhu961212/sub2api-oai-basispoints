# 0.5.22：修复 BPS 429 导致宿主账号误暂停

## 根因

插件接管的请求实际发往 Basis Points，但此前会把其 HTTP 429 原样包装为宿主上游响应。官方宿主无法识别独立的配额来源，会把它送入 Codex 账号限流、重试及账号测试的状态同步流程。因此 BPS 配额问题可能把整个 OAuth 账号暂停。0.5.21 的渠道监控绕行只避免健康检查触发，普通 BPS 请求仍受影响。

## 修复行为

- 只在插件接管的 BPS 请求或原生附件上传返回 HTTP 429 时，发送现有协议的 ForwardResponseError，错误码为 PLUGIN_RATE_LIMITED，并设置 request_sent=true。该标志让官方宿主停止重放本次失败，不进入账号限流写入流程。
- 在图片错误转换之前隔离 429，避免带图片与纯文本请求行为不同。错误说明使用固定安全文本，不复制上游响应体、令牌、图片标识或配额头。
- 未选模型、白名单外账号等透传路径保持原样：真实 Codex 429 仍由宿主正确处理。
- 删除固定算术 challenge 的提示词扫描和特殊绕行；所有请求按模型选择和账号白名单路由。监控选择 BPS 模型时会使用该上游额度，但其 429 不再污染 Codex 限流状态。账号白名单继续用于选择需要插件接管的账号。
- 本次无需修改官方宿主生产代码或插件协议版本。宿主既有错误出口通常返回 HTTP 502；已经开始的流可能返回失败事件。宿主诊断保留 PLUGIN_RATE_LIMITED 和原始 HTTP 429 原因，客户端未必显示该详细诊断。
- 该修复不会增加 BPS 额度，也不会自动清空账号此前的限流、禁用或冷却状态。

## 升级与已暂停账号

在插件管理页升级并重新加载 0.5.22，确认配置页显示运行版本 0.5.22。对已经暂停的账号，先核实是 BPS 429 误记而非真实 Codex 额度耗尽，再在宿主账号管理中清除相应限流状态，或等待原冷却到期。不要批量清除所有账号的真实限流。

一键降智检查通过真实 TestConfig 路径验证：同一测试账号返回 iPhone 17 Pro Max，status=ok，耗时 7.692 秒，结果包含界面需要的状态、答案和账号选择字段。脱敏日志在 dist/live-degradation-0.5.22.log。此结论仅表示该账号通过现有“苹果17”自定义规则，不是通用智力测评。

点击“一键检测”后，会遍历所有当前可调度的 OpenAI OAuth 账号，不受原账号白名单限制；使用第一个已勾选模型（未选时使用默认 Astra）请求配置的 BPS Responses 端点，不检测原生 Codex。每次请求使用该账号自己的凭据和关联代理，无代理时直连。检测结束后，疑似降智账号自动勾选并保存到插件账号白名单；这不改变宿主调度器的账号选择，也不是后台定时检测。HTTP 403 仅表示本次请求被拒绝，单凭状态码无法确认具体原因；失败账号不会被选中。

本次同时修复一键检查的边界：请求改用正式转发的协议构造与 SSE；整体预算 24 秒、单账号 8 秒、并发 8。401/403/429、超时、空白、未完成或失败回答只记为检测错误，不加入疑似降智账号。全失败或无有效结果时保留原选择，保存失败时恢复原白名单。较慢请求可能超过单账号 8 秒，此时会显示检测失败而非误判。
