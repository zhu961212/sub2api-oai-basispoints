# 0.6.0：终态修复、检测接口安全降级与构建修复

> 历史发布记录：以下能力和验证针对 0.6.0。当前版本已移除设备收敛功能、配置开关及设备字段改写；设备相关验证仅供历史参考。

日期：2026-09-27（北京时间，UTC+8）。插件 ID 保持 local.oai-basispoints，签名身份沿用 oai-basispoints-v1 和原 Ed25519 公钥。无需更换宿主已有的受信发布公钥。

发行版本：**0.6.0**。本记录对应双平台签名安装包及其源码；各项验证范围和发行附件如下。

## 本次修复

- **失败终态优先**：真实 SSE event、正文 type、外层与内层 error/status 共用终态判断。失败后清空暂存工具，禁止释放可调用工具完成事件、合并修复结果及缓存成功上下文。空数据、非 JSON、DONE 和矛盾 completed 载荷不能掩盖失败事件。
- **JSON 转 SSE 保留真实结果**：failed、incomplete、cancelled 不再统一写成 completed；失败结果移除可调用工具，取消保留 upstream_cancelled 分类。合成的 created/in_progress 事件不会误带最终 error。
- **缓冲 SSE 锁定首个终态**：失败后追加 completed 不能把请求改成成功；保留 bps_service_rejected 等真实请求级错误，而不是泛化为缺少 completed。
- **主动单账号／批量检测暂停**：官方 Sub2API 0.2.8 的 UI Bridge v1 无法将本次调用与目标账号原子绑定。0.6.0 删除共享配置 save → test → cleanup 检测链，禁用相关按钮并说明原因；TestConfig 在目录、凭据和上游请求之前拒绝旧页面及遗留检测触发。
- **未签名调试构建恢复**：只有明确要求签名时，包装器才自动附加配套公钥验签。残留 publisher.public 不再导致默认未签名构建失败；正式签名构建的 key ID、公钥与强制独立验签要求不变。
- **Windows PowerShell 5.1 构建兼容**：脚本使用 ASCII 注释避免无 BOM UTF-8 被旧解析器误读，并显式按 UTF-8 读取清单、验证 id/version；实际 Windows PowerShell、PowerShell 7 和 Git Bash 包装器均纳入回归。

修复对应 [原审查报告](AUDIT-0.6-PREPARATION.md) 和 [修复验收记录](AUDIT-0.6-REMEDIATION.md)。不声称已证明不存在其他缺陷。

## 兼容性与保留能力

本次没有修改官方宿主。旧 Bridge 主动检测是安全降级，不能表述为“已恢复多页面并发检测”。重新开放检测需要宿主增加经鉴权、按请求绑定目标和配置快照的接口；仅增加 iframe busy 锁、额外读取配置或核对返回账号不能阻止已经派发的错误请求。完整依据见 [检测接口边界](ACCOUNT-CHECK-BRIDGE.md)。

以下能力保留：

- 已选模型／账号转发、原账号凭据与代理、图片附件和工具适配。
- 普通配置保存、被动账号目录和 403 状态查询。
- 宿主普通“测试配置”的 TCP/TLS 连通性检查；它不携带账号令牌、不发送 HTTP 请求，不能证明账号的 BPS 权限。
- 403 自动停用开关、宿主 KV 持久记录及按 block_id 明确重新勾选并保存恢复。关闭自动停用不会清除已有记录。
- 已有检测摘要按账号 ID 展示。底层探测器保留为私有回归入口，不通过旧 UI 接口发起真实检测。

**0.6.0 不解除上游使用政策导致的 HTTP 403，不改变 BPS 账号权限，也不提供固定解禁时长。** 本地插件停用与上游访问限制是不同状态；重新勾选只恢复本地路由，不能保证上游接受请求。

## 覆盖安装

1. 在 Sub2API 插件管理页先停用旧插件及其绑定。
2. 上传相同插件 ID 的 0.6.0 签名安装包；继续使用原 trusted_publishers 公钥。
3. 官方 0.2.8 保留原加密配置和插件 KV；原模型／账号选择与 403 停用记录继续保留。
4. 更新会重建绑定，状态为停用、灰度比例为 100%。先重新设置所需灰度，再启用插件及绑定。
5. 重开配置页，确认运行版本为 0.6.0、账号状态和配置项；确认单账号／批量检测按钮显示暂停原因。普通保存并读回确认会清除旧检测触发。
6. 不要把“测试配置”连通性成功理解为 BPS 权限或真实推理成功。
